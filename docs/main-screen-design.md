# 메인 화면 설계

> 2026-10-01 `/grill-me` 세션으로 확정. 백엔드 연동 없이 목 데이터로만 구현한다. 요청하지 않은 기능은 추가하지 않고, 추천 기능은 아래 리포트에만 남긴다.

## 컨셉

아늑하고 살아있는 카페. 공부·작업하기 좋은 분위기. 웹 기반이며 모바일에서도 사용 가능해야 한다.

## 라우트

| 경로 | 화면 |
|---|---|
| `/` | 랜딩 |
| `/login` | 로그인 |
| `/signup` | 회원가입 |
| `/home` | 홈 (세션·포인트·상점 진입) |
| `/shop` | 상점 (준비 중 페이지) |

- 로그인 상태로 `/`, `/login`, `/signup` 진입 → `/home`으로 이동
- 로그아웃 상태로 `/home`, `/shop` 진입 → `/`로 이동

## 인증 (목)

목 API는 백엔드 회원 API(아래 "백엔드 회원 API" 참고)와 같은 요청·응답 모양으로 만든다.

- **랜딩**: 카페 장면 히어로 + 한 줄 소개 문구 + 로그인·회원가입 버튼
- **회원가입**: 이메일, 비밀번호 입력 → 닉네임 설정 창 → 확정 시 `signup({ email, password, nickname })` 한 번 호출 → 로그인 화면으로 이동
  - 백엔드는 세 값을 한 요청으로 받으므로, 닉네임 창은 가입 요청 전 마지막 입력 단계로 둔다
  - 닉네임: 2~10자, 빈칸 불가, 설정 전에는 창을 닫을 수 없음
  - 이미 가입된 이메일 → `EMAIL_ALREADY_EXISTS` "이미 사용 중인 이메일입니다"
- **로그인**: `localStorage`에 저장된 목 회원 정보와 이메일·비밀번호를 대조
  - 가입되지 않은 이메일 → `MEMBER_NOT_FOUND` "회원을 찾을 수 없습니다"
  - 비밀번호 불일치 → `INVALID_PASSWORD` "비밀번호가 일치하지 않습니다"
  - 성공 시 가짜 `accessToken`, `refreshToken`을 반환하고 `localStorage`에 저장
  - 비밀번호를 평문으로 저장 (목 단계 한정)
- 토큰이 있으면 로그인 상태로 보고 새로고침해도 유지. 로그아웃 버튼으로만 로그아웃(`logout` 호출 후 토큰 삭제)
- 토큰 만료·재발급(`refresh`)은 목에서 흉내 내지 않는다

## 홈

### 레이아웃

- 배경 전체가 카페 장면, 상단 헤더, 가운데 큰 타이머
- 헤더: 닉네임, 포인트, 상점 진입, 테마 토글, 로그아웃
- 모바일도 같은 구조. 헤더에는 포인트 + 메뉴 버튼만 두고 상점·테마·로그아웃은 메뉴 안에 둔다
- 장면 위 글자 가독성을 위해 타이머 영역에 반투명 패널

### 세션

상태 흐름: `대기 → 진행 ↔ 일시정지 → 목표 달성(완료 대기) → 결과`

- 목표 시간: 프리셋 25 / 50 / 90분, 카운트다운
- 일시정지: 남은 시간이 멈춤, 횟수·시간 제한 없음, 일시정지 중에는 타이머 숫자를 흐리게 표시
- 목표 달성: 타이머가 0에서 멈추고 "완료하기" 버튼을 눌러야 완료. 완료 대기 상태도 저장되어 새로고침·재접속 후에도 유지
- 중도 종료: 확인 창에서 받을 포인트를 미리 보여줌 (예: "지금 종료하면 24P를 받습니다")
- 세션 중에는 세션 외 요소를 흐리게 처리
- 타이머 접기: 세션 시작 후 타이머 창을 접을 수 있다. 접으면 화면 아래쪽에 남은 시간이 보이는 작은 알약만 남고, 누르면 다시 펼쳐진다
- 결과: 카페 영수증 모양 카드로 목표 시간·집중한 시간·적립 포인트를 보여주고 포인트 숫자가 올라가는 연출

### 포인트 (목 규칙)

- 공부한 시간(일시정지 제외) 1분당 1P, 1분 미만은 버림
- 10분 미만이면 0P (완료·중도 종료 공통)
- 시작 포인트: 1,240P

### 새로고침·탭 닫기

- 새로고침: 이어서 진행
- 탭을 닫았다 다시 열기: 일시정지 상태로 표시. 마지막으로 탭이 열려 있던 시각까지만 공부 시간으로 계산
- 구분 방법: `sessionStorage`(새로고침 시 유지, 탭 닫으면 삭제) + 마지막 활성 시각을 주기적으로 저장
- 탭 전환·앱 전환 중에는 타이머가 계속 흐름

## 분위기

- 따뜻한 색감·타이포 중심 UI + SVG 카페 장면 (랜딩과 홈에서 같은 장면 재사용)
- 움직임: 커피 김, 조명 두 가지. 세션 중에는 더 잔잔하게. OS "동작 줄이기" 설정 시 정지 (`MotionConfig reducedMotion="user"`)
- 에셋 없음 → CSS/SVG + 무료 웹폰트 (Pretendard 계열)
- 시각 디자인 세부(색·폰트·간격·모션)는 `DESIGN.md`를 따른다

### 카페 소음

- 커피머신, 타자, 대화 소리가 섞인 카페 앰비언스를 반복 재생
- 무료 음원(출처 표기가 필요 없는 라이선스)만 사용
- 헤더에 전체 on/off + 볼륨 하나. 소리별 조절은 하지 않는다
- 기본값은 꺼짐 (브라우저 자동 재생 정책상 사용자가 눌러야 재생 가능). 설정은 `localStorage`에 저장

### 시간대별 장면

| 구간 | 시각 |
|---|---|
| 아침 | 6~11시 |
| 낮 | 11~17시 |
| 저녁 | 17~20시 |
| 밤 | 20~6시 |

- 사용자 기기 시각 기준, 경계 시각은 상수 하나로 관리
- 1분마다 확인하고 구간이 바뀌면 몇 초에 걸쳐 전환
- 개발 모드에서만 `?time=night`처럼 구간을 강제 지정 가능

### 다크 모드

- UI(패널, 글자, 버튼)만 어둡게. 장면은 시간대만 따른다
- 기본값은 OS 설정, 토글로 변경 가능, 선택은 `localStorage`에 저장
- 장면과 UI 테마가 엇갈려도 튀지 않도록 패널은 반투명

## 데이터

- 목 API 함수(로그인, 회원가입, 내 정보, 포인트 등)가 약간의 지연 후 Promise를 반환
- 화면은 TanStack Query로 호출, 저장소는 `localStorage`
- 목 응답도 백엔드 공통 포맷 `{ success, code, data, message }`을 따른다
- 백엔드 연동 시 목 함수 내부만 `fetch`로 교체

## 백엔드 회원 API (2026-10-01 확인)

JWT 기반. 액세스 토큰은 HS256 JWT(subject = memberId), 리프레시 토큰은 DB에 저장되는 UUID이며 재발급 시 교체(로테이션)된다.

| 메서드·경로 | 인증 | 요청 | 응답 `data` |
|---|---|---|---|
| `POST /api/v1/members/signup` | 불필요 | `{ email, password, nickname }` | 없음 |
| `POST /api/v1/members/login` | 불필요 | `{ email, password }` | `{ accessToken, refreshToken }` |
| `POST /api/v1/members/refresh` | 불필요 | `{ refreshToken }` | `{ accessToken, refreshToken }` |
| `POST /api/v1/members/logout` | `Authorization: Bearer <accessToken>` | 없음 | 없음 |
| `GET /api/v1/members/me` | `Authorization: Bearer <accessToken>` | 없음 | `{ memberId, email, nickname }` |

- 만료: 액세스 24시간, 리프레시 14일
- 로그인하면 기존 리프레시 토큰을 지우고 새로 발급 (다른 기기 로그인 시 이전 기기의 리프레시 토큰 무효)
- 인증 실패: 401 `UNAUTHORIZED`, 권한 없음: 403 `FORBIDDEN`

- 입력 검증: 실패 시 400 `INVALID_INPUT`, `message`에 첫 번째 필드 오류 문구
  - 이메일: 빈 값 불가, 이메일 형식
  - 비밀번호: 빈 값 불가, 8~20자
  - 닉네임: 빈 값 불가, 2~10자
- 로컬 CORS 허용 출처: `http://localhost:5173` (Vite 기본 포트)
- 2026-10-01 백엔드에서 `/me`, 입력 검증, CORS 변경 완료 (테스트 31개 통과)

## 알려진 한계 (목 단계에서 감수)

- Chrome "닫은 탭 다시 열기"는 `sessionStorage`도 복원해 새로고침으로 판단되고, 닫혀 있던 시간도 공부 시간으로 계산될 수 있음
- 같은 홈을 탭 두 개로 열면 상태가 꼬일 수 있음
- 백엔드 연동 시 서버 시각 기준으로 정리

## 다음 작업: 카페 손님과 1:1 대화 (이번 범위 아님)

2026-10-01 결정. 메인 화면을 먼저 완성하고 별도 작업으로 설계한다.

- 장면에 손님이 무작위 자리에 앉아 있다. 손님은 **실제 접속 중인 사용자 + NPC** 둘 다
- 손님을 누르면 1:1 대화. 실제 사용자 간 대화는 WebSocket + STOMP, NPC 대화는 백엔드 RAG(npc) 도메인과 연결
- 설계할 것: 접속자 현황(presence), 자리 배정, 대화 수락·차단·신고, 공부 중 대화가 집중을 깨지 않게 하는 규칙, NPC 표시 구분

## 추천 기능 리포트 (구현하지 않음)

- 빗소리 등 카페 외 앰비언트 사운드, 소리별 믹서
- 목표 달성 알림: 알림음, 브라우저 알림, Sonner 토스트
- 세션 기록·통계: 오늘 공부 시간, 연속 공부일
- 목표 시간 직접 입력, 개발용 1분 프리셋
- 닉네임 변경
- 비밀번호 보기 토글, 비밀번호 찾기
- 랜딩 서비스 소개 섹션
- 여러 탭 동기화 (`storage` 이벤트), 서버 시각 기준 세션 계산
